Describe an MQTT digital-twin pipeline from deterministic simulation through validated publishing and InfluxDB storage, including recovery signals and sequence-based loss measurement.

OUTPUT
The system simulates one boiler asset and publishes deterministic telemetry at a fixed interval. The simulator calculates supply temperature, return temperature, ambient temperature, setpoint and power draw from a UTC timestamp and asset configuration. It is a pure function, so identical inputs produce identical readings.

The publisher wraps those readings in a versioned JSON payload containing the asset ID, timestamp and monotonically increasing sequence number. Messages are published to an asset-specific MQTT topic. Scheduling is based on deadlines calculated from one monotonic start time, preventing processing time from accumulating as clock drift.

Structured logs expose connection, publication, storage and recovery events. Sequence gaps are recorded when received messages skip expected values. Experiments compare the publisher sequence range with sequences stored in InfluxDB to measure message loss. Storage recovery is reported only on the first successful write after one or more failures. Grafana reads stored data and displays temperature, power, message rate and the latest sequence.

OUTPUT
def latest_completed_run(entries: list[dict]) -> tuple[dict, dict]:
    started = None
    completed = None
    for entry in entries:
        if entry.get("event") == "started":
            started = entry
        elif entry.get("event") == "stopping" and started is not None:
            completed = (started, entry)
            started = None
    if completed is None:
        raise RuntimeError("publisher logs contain no completed run")
    return completed

class WriteFailureState:
    def __init__(self):
        self.failures = 0

    def record_failure(self) -> None:
        self.failures += 1

    def record_success(self) -> int:
        failures = self.failures
        self.failures = 0
        return failures

After a successful database write, handle_message calls record_success. It emits a write_recovered log only when the returned failure count is greater than zero. A second successful write returns zero and therefore produces no additional recovery log.

def test_successful_connack_returns_and_restores_callback(self):

    with patch.object(mqtt.Client, "tls_set"):
        client = build_client(config, "id-12", "test.connack")

        reason_code = ReasonCode(PacketTypes.CONNACK, identifier=0)
        client.on_connect(client, None, {}, reason_code, None)

    assert client.on_connect is original_on_connect
